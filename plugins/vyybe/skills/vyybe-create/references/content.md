# Content: hooks, structures and copy

## Hooks that stop the scroll (slide 1, thumbnails, ad headlines)
Pick the pattern that fits the topic; be specific to the user's subject.
- **Outcome**: "I stopped SSH-ing into my server."
- **Number + promise**: "5 prompts that run my VPS for me"
- **Contrarian**: "Your landing page doesn't need more features."
- **Mistake**: "The 3 pricing mistakes that cost me $40k"
- **How-to**: "How I write a week of posts in 30 minutes"
- **Before → after**: "From 4h of reporting to 10 minutes"
- **Question that hurts**: "Still copy-pasting commands from Notion?"
- **Insider/secret** (only if true): "What nobody tells you about cold email"
Rules: concrete nouns and numbers beat adjectives; ≤ 10 words; no clickbait the content can't deliver.

## Carousel structures
- **Educational / how-to**: Hook → Problem → (why it matters) → Steps 1…n (one per slide) → Recap → CTA
- **Listicle**: Hook ("7 tools…") → one item per slide (name + why + tiny example) → Summary → CTA
- **Story**: Hook (the moment) → Context → Struggle → Turning point → Result (numbers if real) → Lesson → CTA
- **Comparison**: Hook → Option A → Option B → Side-by-side table → Verdict → CTA
- **Myth vs fact**: Hook → Myth/Fact pairs (one per slide) → Takeaway → CTA
- **Framework**: Hook → The framework at a glance → One slide per part → How to apply → CTA
Typical length: 5–8 slides for Instagram, 6–12 for LinkedIn. Fewer, stronger slides beat filler.

## Copy rules
- One idea per frame. Headline carries the message on its own; body supports it.
- Body ≤ ~30 words per slide (LinkedIn ≤ 40). Prefer lines/bullets over paragraphs.
- Use the user's words and voice (branding `voice` wins). Second person ("you") works for educational content.
- Show, don't tell: a real example, a command, a mini-screenshot mock, a number.
- CTAs: one per piece, specific: "Save this for your next deploy", "Follow @handle for weekly dev workflows", "Comment 'GUIDE' and I'll send it".
- Never invent statistics, quotes, testimonials, prices, results or customer names. If the design needs proof the user hasn't given, use a placeholder clearly marked for them to fill (e.g. "[your result]") and tell them.

## From a URL, article or notes
- Extract the 3–7 most useful, concrete points. Keep the author's claims attributable; don't add facts.
- Rephrase into hooks and slide headlines; don't paste long sentences.
- If you can't fetch the URL, say so and ask the user to paste the text.

## Thumbnails
- 2–5 words that add curiosity to the video title (title: "How I automated my server" → thumbnail: "I QUIT SSH").
- Emotion + object + few words. Make 3 different concepts when asked for options.

## Ads
- Formula: pain or desire → benefit → proof (if real) → CTA button ("Start free", "Get the guide").
- Headline ≤ 7 words; CTA button text ≤ 3 words.
